# Go Multi-Module Hexagonal Architecture

## 목표
멀티모듈 및 헥사고날 아키텍처를 Go Gin 프레임워크 위에서 구현합니다.

이를 통해 각 아키텍처에 대해 이해하고, 향후 프로젝트에서도 보일러 플레이트로 사용할 수 있도록 하는 것이 목표입니다.

유저 도메인을 통해 도메인의 adapter - port 구조, ORM, token 모듈을 통한 infrastructure 통합 등을 구현하여 실제 프로덕션 환경에서도 활용 가능한 아키텍처를 구성합니다.

### Hexagonal Architecture (헥사고날 아키텍처)

헥사고날 아키텍처는 포트와 어댑터 패턴이라고도 불리며, 도메인 중심의 설계를 지향합니다.

#### 주요 특징
- **도메인 중심 설계**: 비즈니스 로직을 중앙에 배치하고 외부 의존성으로부터 격리
- **포트(Port)**: 도메인이 외부와 통신하기 위한 인터페이스 정의
- **어댑터(Adapter)**: 포트의 구체적인 구현체로, 외부 시스템과의 실제 연결을 담당
- **의존성 역전**: 도메인이 인프라스트럭처에 의존하지 않고, 인프라스트럭처가 도메인에 의존

### Multi-Module Architecture (멀티모듈 아키텍처)

멀티모듈 아키텍처는 대규모 애플리케이션을 여러 개의 독립적인 모듈로 분리하여 관리하는 방식입니다.

#### 주요 특징
- **모듈화**: 기능별, 도메인별로 코드를 분리하여 관리
- **재사용성**: 공통 기능을 별도 모듈로 분리하여 여러 프로젝트에서 재사용
- **독립적 개발**: 각 모듈을 독립적으로 개발, 테스트, 배포 가능
- **의존성 관리**: 모듈 간 의존성을 명확히 정의하고 순환 참조 방지

#### 이 프로젝트의 모듈 구성
- **domain**: 핵심 비즈니스 로직과 엔티티
- **application**: 유스케이스와 비즈니스 규칙
- **infrastructure**: 외부 시스템과의 연동 (DB, API 등)
- **presentation**: HTTP 핸들러, REST API 엔드포인트
- **shared**: 공통 유틸리티와 설정

#### 장점
- 코드의 명확한 경계와 책임 분리
- 병렬 개발 가능
- 테스트 용이성 향상
- 유지보수성 개선
